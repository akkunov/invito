Кандидат повторной визуальной приёмки. База сравнения — `d68201bbf573563ed29150044f9716256f680238`, merge PR #80. Ручная приёмка владельца ожидается. [Карточка VF-01](../architecture/tasks/VF-01-love-story.md)

## Локальный просмотр без базы данных

1. Выполните `npm ci` в корне проекта.
2. В первом терминале запустите `node scripts/fixtures/love-story.mjs`. Fixture слушает только `127.0.0.1:4281`, читает пакет из файла, возвращает синтетические ответы RSVP и ничего не сохраняет.
3. Во втором терминале соберите и запустите приложение с адресом локального fixture.

   ```bash
   NEXT_PUBLIC_API_URL=http://127.0.0.1:4281/api/v1 npm run build
   NEXT_PUBLIC_API_URL=http://127.0.0.1:4281/api/v1 npm run start -- --hostname 127.0.0.1 --port 4280
   ```

4. Откройте [приглашение RU](http://127.0.0.1:4280/ru/c/love-story), [приглашение KY](http://127.0.0.1:4280/ky/c/love-story) или [редактор](http://127.0.0.1:4280/ru/editor?template=love-story). Для тестового отказа API используйте имя `Сбой`. Варианты `love-story-long`, `love-story-closed` и `love-story-unavailable` показывают длинные данные, закрытую форму и недоступность приёма.
5. Для автоматического повтора укажите папку с установленным Playwright в `STUDIO_BROWSER_PREFIX`. Можно использовать системный Chromium через `CHROMIUM_PATH`.

   ```bash
   npm install --prefix /tmp/eventiq-vf-01-browser playwright
   /tmp/eventiq-vf-01-browser/node_modules/.bin/playwright install chromium
   STUDIO_BROWSER_PREFIX=/tmp/eventiq-vf-01-browser \
     node scripts/fixtures/capture-love-story.mjs /tmp/eventiq-vf-01
   ```

Для базового сравнения сохраните `git show d68201b:templates/packages/love-story.v1.json > /tmp/love-story-before.json`. Запустите fixture с этим файлом как первым аргументом и откройте приложение от того же базового SHA. Режим `--capture-only` снимает исходные четыре артборда без тестов новых вариантов.

## Источники и совместимость

Источники — четыре неразмеченных PNG, `geometry.json`, спецификация, HTML-прототип и семь исходных WebP. У исходных демо-фотографий часть кадров обрезана, а два кадра содержат номер главы. Для кандидата использованы отдельные очищенные фрагменты заданного референса: фотографии, рамки, ветви, билет, марка и декоративные края. Номера глав, подписи, заголовки, время, дата и поля формы отрисовываются поверх. Бумажное зерно подготовлено отдельно. Точные размеры и байты читает `npm run templates:compile -- love-story`.

Кандидат использует те же slug и ID полей. URL ранее опубликованных ресурсов и их файлы сохранены. Новые ресурсы имеют префикс `/images/collection/love-story/vf-01/`. Файл `love-story.v1.json` по-прежнему использует формат пакета v1. Его обновление в рамках этого PR не публикует версию в базе. Импорт и переключение публичной версии относятся к [TPL-02](../architecture/tasks/TPL-02-append-template-version.md) и [TPL-04](../architecture/tasks/TPL-04-template-version-rollout.md).

Движок использует опциональные параметры текста и виджетов. Старые документы без этих параметров продолжают работать по прежним правилам. Остальные случаи для общего движка зафиксированы в [ENG-01](../architecture/tasks/ENG-01-renderer-fidelity-contract.md#наблюдения-vf-01) и [ENG-02](../architecture/tasks/ENG-02-renderer-optional-capabilities.md#наблюдения-vf-01).

## Измерения и проверки

Доля пикселей, у которых хотя бы один из трёх каналов RGB отличается от оригинала более чем на 24 из 255. Это индикатор масштаба изменений и подсказка для ручной проверки.

| Артборд | Before | After |
| --- | ---: | ---: |
| 01 · Обложка | 50,8% | 5,4% |
| 02 · История | 39,6% | 13,5% |
| 03 · Билет и программа | 42,8% | 9,4% |
| 04 · RSVP | 33,6% | 9,9% |

- Browser подтвердил живой рендер. Playwright Chromium 156 подтвердил четыре артборда 390 × 1045 при DPR 1, 12 гостевых экранов RU/KY на 320/360/375/390/412/430 px, длинные имена и описание главы, изменение имени в клиентском редакторе, переход к истории и выгрузку календаря с `DTSTART:20270529T110000Z`. Для карты проверена сгенерированная ссылка.
- RSVP проверен со статусами пустого имени, отправки, ошибки API с сохранением пожелания, отказа с нулём гостей, успеха, закрытия и недоступности. Все запросы были локальными. В браузерной проверке не было необработанных ошибок JavaScript.
- Frontend/backend typecheck и production build прошли. Прошли 20 frontend/контрактных наборов и 19 backend unit-тестов. В их числе `test:template-assets` (20/20), `test:template-collection` (13/13), `test:mobile-editor-v3` (16/16), а также приглашения, layout, responsive, appearance, registry, linked components, персонализация, редактор, backend contract и пакеты семи существующих шаблонов. Контрактный тест заменяет по очереди все шесть фото и проверяет неизменность геометрии и блокировки декора. Загрузка в R2 и production-публикация не входили в проверку.
- Полный lint остался на исходных 52 ошибках и 52 предупреждениях. Отдельный PostgreSQL для визуальной проверки не требовался. Ручная визуальная приёмка и проверки на физических телефонах остаются открыты.
