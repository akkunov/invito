# ADR-017 — Template output and preflight (#28.7.2)

The selected template's latest immutable snapshot is the input to export. The offscreen capture mounts the existing StudioV2Artboard inside the Studio stylesheet, resolves authored tokens/bindings, measures intrinsic text and solves layout. It embeds loaded raster image data and computed styles in an SVG foreignObject, and rasterizes to a bounded opaque white RGB canvas. No separate canvas drawing implementation of invitation nodes or effects. This path is intended for Chromium; SVG foreignObject and canvas behavior differ across browsers, especially Safari. Failures are reported rather than silently replacing assets.

PNG exports include the requested physical DPI in a pHYs chunk (replacement with CRC). PDF is a single-page lossless Flate-compressed RGB raster with the matching physical MediaBox and pixel dimensions. The width is chosen in mm, height follows the measured artboard aspect ratio. The A5/A6 presets specify width only, not a forced ISO page ratio. Supports 150/300/600/1200/2400 DPI, limits 16,384 px width, 32,768 px height and 200 million total pixels. Above 8 million pixels or 8192 px per axis, the renderer rasterizes full-width strips of at most 2 million pixels, using a shared global pixel grid. PNG uses a single streamed Deflate sequence with Sub-filtered rows and multiple IDAT chunks; PDF uses independently compressed lossless RGB strip XObjects placed in physical page coordinates. Compressed output is capped at 256 MB. Progress and abort are available between strips. High-DPI export is recommended on desktop; very large compressed files and browser memory limits can still prevent completion. Browser capture has no guarantee of CMYK, PDF/X, vector text, crop marks, bleed, spot colors or professional color profile conversion. Static widget rendering is a snapshot, not an interactive PDF. No animation playback. A higher export DPI cannot increase source-photo detail; estimated image DPI warnings are advisory. Only a selected canonical page is exported, no automatic whole-site print or multi-page PDF.

Cover generation uses the same capture, limits output to 800×1200, and caches PNG in IndexedDB keyed by template ID, version and cover page. Gallery renders the cached cover when available and falls back to live artboard. New versions do not reuse old cover images. The portable template package remains self-contained for the source design, not the derived cover cache.

Readiness checks validate the document schema, visible cover and empty pages, presence of declared local and bundled assets, empty values/content widgets, and possible clipped layout geometry for responsive profiles. Missing resources and hidden/empty cover block transition to local ready. Warnings are advisory and intentional cropping may be valid. It is not a complete accessibility, typography, color or server publication certification. Full public publishing remains #29.

Theme variants create a new independent template and version 1 from the selected existing theme (or baseline). Existing IDs and snapshots are untouched. This is not yet a cross-project shared theme catalog.

Tests: npm run test:studio-v2-template-output verifies pixel/physical conversions, PNG metadata, PDF offsets/stream, readiness and theme fork. Chromium integration exercises import with actual local assets, export of nonblank artwork, PNG DPI and physical PDF, cover generation and variant, a striped 1200 DPI PNG compared to normal artwork, and 2400 DPI PDF strip coverage. CI is required before merge. Manual Safari and professional press proof remain follow-up.
