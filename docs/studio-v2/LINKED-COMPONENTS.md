# ADR-012 — Linked Components & Variants (#28.3)

A linked instance is a materialized document subtree with a componentRef on its root and a stable componentSourceId on every member. A master variant is an independent, validated tree in the library. It is not a mutable pointer to an arbitrary artboard. The author selects an ordinary source layer or a complete instance and clicks "Обновить мастер из выделения" for the chosen variant; this explicit commit atomically reconciles all linked instances of that variant in the document. Editing an instance does not silently edit the master. Legacy snapshots with a componentRef but no source keys remain detached snapshots; no existing appearance is overwritten on load.

Field overrides: normal authored update/move/layer-state commands record changed top-level fields on each linked member. A linked root's x/y/rotation are independent placement, not master fields for propagation. Overrides persist even if the master later happens to equal the override. Reset layer or reset instance removes overrides; detach removes linkage without changing the current appearance. Shared nested objects such as visual, sizing, runs and widget config are overridden as whole fields; a user can reset them as a group. Device-specific overrides remain separate and survive for retained IDs. Removed master layers remove their device overrides.

Stable source IDs and node types preserve instance IDs and overrides on master changes and variant switches. Newly added layers obtain deterministic collision-safe IDs and obsolete layers disappear. Root ID and position are retained. New variants made from a selection map corresponding compatible tree paths to base source keys; master replacement prefers original source IDs, so unrelated source layers become new members. For structural updates use the original source/master selection rather than unrelated layer trees. Variant roots must have compatible types.

Instance structure is protected by schema validation: detach before structural editing. Complete linked subtrees can be copied/duplicated within a project and keep their links; clipboard copies of just an inner linked layer are detached. Nested frames are supported, but independently linked components *inside* an instance are deliberately not supported in this release. A snapshot of an ordinary frame containing instances flattens those links. Cross-project shared definitions and true nested linked definitions require additional library/versioning work; they are not claimed implemented.

Insertion, master update, variant switch, reset and detach are history-backed commands. All reconciliation is atomic and validated; no runtime DOM manipulation or duplicated renderer. The existing artboard and public-preview rendering path reads materialized nodes as before. No backend or legacy invitation changes.

Regression suite: npm run test:studio-v2-linked-components. Chromium exercises create, insert, override, master update, variant switch and reset; screenshots are attached by CI. Do not merge pending/failing checks. Follow delivery policy in DELIVERY.md.
