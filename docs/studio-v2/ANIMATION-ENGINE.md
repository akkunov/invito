# ADR-014 — Animation Engine & Timeline (#28.5)

Nodes have optional declarative motion specs (preset, trigger, duration, delay, easing, distance, starting scale). Validation bounds all values and allows only predefined presets and easings. Parallax is paired with scroll; other presets support load, viewport, hover and click. No executable user code, remote motion scripts or arbitrary CSS. Existing schema-version-2 documents remain valid.

The shared Artboard attaches Web Animations API effects in presentation only. Studio canvas remains static. Separate CSS translate and scale properties compose with authored rotation and reflection rather than replacing them. Opacity returns to authored opacity, not always 1. Reveal falls back to fade for nonrectangular existing masks to preserve clip geometry. Motion never mutates authored document or layout. Viewport animation runs once; hover/click replays on each trigger without hiding idle content. Parallax tracks page visibility progress inside either the preview scrolling region or browser viewport. Its delay/duration affect timeline simulation, not live scroll position. Root-page motion is supported. Animations, observers, listeners and RAF callbacks are cleaned up on unmount/config change. Reduced-motion visitors see the static final authored state. Focus entering a pending entrance animation reveals the target to preserve keyboard usability. Browser without WAAPI displays normal content. No perpetual animation loops.

Timeline displays all visible animated layers in document order, including root frames. The playhead is shared across the real presentation artboards; users can play, pause, reset or scrub the simulated time. The simulation starts all trigger tracks at their configured delay; it is not an exact recording of guest scrolling/hover/click. Timing editing lives in the inspector. Multi-selection Stagger creates a viewport entrance per selected layer with increasing delays, in selection order, as one atomic history entry. Motion inherits through master components and can be overridden/reset/detached per instance. Existing legacy invitation routes remain unchanged.

Scope limitations: one motion preset per node, no arbitrary keyframe editing, path drawing or vector path morphing, additive multiple tracks, cross-page synchronized guest timeline or scroll-bound event program yet. Timeline bars visualize timing and are not directly draggable. Timeline and live mode are isolated; live guest actions continue to use existing guest adapters. Mobile Safari/manual device verification is separate from Chromium.

Regression: npm run test:studio-v2-motion. Chromium tests verify authored canvas unchanged, actual presentation scrub (zero/intermediate/final opacity), reduced motion and live replay. Static Pages deployment shares the same renderer. Merge only after current-head quality/browser checks pass.
