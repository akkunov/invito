# ADR-013 — Design Tokens & Shared Styles (#28.4)

The project owns a typed token registry: colors, solid/gradient fills, typography, strokes, effects (shadow + blur) and independent corner radii. Nodes carry optional slot references. A single color can bind both fill and text color. References are validated against compatible token kinds in the document and master variants. Old documents require no migration. Token IDs are immutable; tokens used by nodes or master variants cannot be deleted. Theme deletion removes its overrides and returns to the base theme if active.

A theme contains typed overrides of base tokens and cannot introduce new token IDs or change token kinds. The active theme is project-wide. Missing theme values inherit the base. The style resolver runs after content binding and before layout for both the editor and responsive preview. It preserves raw authored document, text, topology and component metadata. In rich text, typography applies family, size, weight, line height and letter spacing across runs; colors use a separate slot. Underline, italic and strike are not overridden by typography. Text remains editable. Local fallback edits to controlled visual fields are blocked in the inspector until the corresponding slot is unlinked. Unlink materializes the effective current slot value while leaving other slots linked. The existing text editor may materialize effective run styling as part of text editing; the shared slot remains authoritative while linked.

Master component snapshots and instances retain token IDs; a token update or active theme changes their presentation without reconciling or replacing the instance tree. A local change to an instance's tokenRefs is a top-level component override; other fields retain normal behavior. Unlinking a slot on an instance materializes its current value as an instance override. Undo/Redo is provided by the command engine. Device overrides remain separate.

The inspector has a project style library with create/edit/delete, compatible layer binding selectors, theme creation/deletion, active theme switching and per-theme token override/reset. Existing geometry, widgets and other invitation routes are unchanged. Tokens apply to the outer layer of widgets; widget-specific content theme remains independent. Corners do not override inherent circle/ellipse shape geometry. Typography currently uses the supported Arial and Georgia font families; uploaded fonts, cross-project libraries, theme previews in the catalog, theme export to CSS, spacing tokens and per-device typography are follow-up scope.

Tests: npm run test:studio-v2-style-tokens. The Chromium suite exercises two linked text layers, theme edit, mobile preview, detach and undo. Existing regressions and both Pages CI workflows remain required. No merge before passing checks.
