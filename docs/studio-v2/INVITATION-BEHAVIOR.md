# ADR-009 — Invitation behavior and typed bindings (#28)

A widget is an ordinary selectable document node with validated configuration and document-owned appearance. Six kinds are supported: RSVP, countdown, location, gallery (up to four assets), music, schedule. All text settings are RU/KY; the editor chrome follows existing Studio conventions. Native input/select controls remain platform-owned. Widget appearance is independent of public shell / editor UI tokens.

Variable definitions remain in variables; optional typed values live in values. Text values have RU and KY strings; dates are explicit ISO instants with an offset or Z; date display uses Asia/Bishkek. Number and boolean formatting follows the document locale. A bound text node displays the value using the first run style, and editing preserves its original fallback text. Countdown can bind only a date, location only text. Missing values retain fallback. The renderer resolves bindings before responsive layout, without mutating the source. Component snapshots validate their widget asset and variable references too.

Studio mode is inert. Preview mode validates RSVP and explicitly says nothing was sent. No guest data is persisted in project JSON/IndexedDB; form state lasts only while mounted. Live mode requires an injected transport; the server must independently authenticate the invitation context, validate the deadline/count and implement idempotency/rate limits in #29. No transport or publication endpoint exists yet. Never treat a preview as a live submission.

Countdown uses a real clock and clamps expired values to zero; map links are constructed from encoded addresses, not arbitrary executable URLs. Gallery uses existing asset references. Music accepts a restricted HTTPS audio file URL or a same-origin /audio/ path, starts only via user interaction and stops on unmount. No autoplay or audio upload yet. Opening a map or playing external audio intentionally contacts that provider; preview does not submit guest data. Fixed widget dimensions can be resized in Studio. Schedule items have localized labels and explicit times; no scroll animation is added in this phase.

Regression suite: npm run test:studio-v2-invitation; previous suites, TypeScript and production build remain in CI. Browser QA must exercise desktop/mobile, RU/KY, keyboard/focus, missing gallery assets, playback errors, expired dates, preview form success/error, and no network submission. Existing legacy routes and templates are unchanged.
