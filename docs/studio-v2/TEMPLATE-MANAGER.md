# ADR-016 — Local Template Manager (#28.7.1)

The template registry is separate from editable projects. A template has stable metadata (name, category, description, tags, cover page and draft/ready state) and an ordered list of immutable, validated Studio v2 snapshots. New versions and restores append to history; they never overwrite earlier snapshots. A clone makes a new template ID and a new initial version. Editing a saved template opens an independent project with a fresh project ID; the original design and earlier versions remain intact. To update the template, explicitly save the current workspace as a new version. Local projects are selectable in the manager, and the active project is restored on reload.

The manager supports six categories, search and status filtering, live cover artboard previews, choice of cover page, blank designs and designs saved from the current project. It does not duplicate rendering logic. The gallery mounts at most twelve initial covers and loads more on demand. Metadata and versions use IndexedDB; database upgrade preserves previous projects and images. Both a template snapshot and its editable fork reference immutable image storage keys. Deleting a template does not remove shared blobs or projects.

The portable format is .invito.json with format "invito-template", version 1, metadata, the latest validated document, and base64-encoded raster images for every declared asset. Both bundled and local images are included. Import validates the format, document and exact asset set; checks size limits and raster headers and decodes images; assigns fresh local storage keys; writes the template and media atomically. Import never overwrites a source template or workspace. PNG/JPEG/WebP only; uploaded SVGs are already rasterized by Studio. Total media limit 80 MB, package limit 115 MB, 200 assets, 50 MB per asset. Export is a latest-version portable snapshot, not a full historical backup. Template history is limited to 50 versions. Storage is browser-local and can be cleared independently of exported packages.

Ready status is a local workflow flag only; not a server publication or public URL. Public publishing, permissions, server storage and concurrency checks belong to #29. Full historical backup, generated PNG/PDF print export, automatic cover rasterization and cross-project shared library synchronization are follow-up scope. No changes to the legacy invitation routes.

Tests: npm run test:studio-v2-template-registry. Chromium checks create, version, restore, duplicate, filter, real package download/import, independent project open, reload and return to original. Both CI workflows include the new regression suite. Merge only when current-head checks pass.
