# ST-01 — Матрица профессионального Admin Studio v2

Приоритет `P1`. [Реестр задач](../PROJECT-STATUS.md)

## Цель

Зафиксировать воспроизводимый авторский workflow и приоритеты именно существующих возможностей.

## Текущее состояние

Есть объединённый холст, команды, local/remote storage и реализация Template Manager. Роль и режимы влияют на действия.

## Зависимости

[000](000-eventiq-4-1-foundation.md)

## Scope

Сценарии выбор/слои/zoom/undo, медиа, правки виджетов, тестовый экспорт, режимы offline и cloud.

## Non-goals

Новый Studio, замена командной модели и изменение гостевого UI.

## Архитектурные требования

Использовать document-first и capability/role boundaries, подтверждать рабочее состояние на реальных сценариях.

## План реализации

Проверить сценарии на локальном и тестовом workspace; описать gap map, baseline многослойности и авторские приоритеты.

## Acceptance Criteria

Для каждой области указан путь к коду, сценарий, результат и дальнейшая узкая задача по подтверждённой проблеме.

## Обязательные тесты

test:studio-v2-core/commands/ui, canvas smoke, manual keyboard/IME and browser characterization.

## Миграции

Нет.

## Rollback Plan

Документацию уточнить по доказательствам; код и данные не затрагивать.

## Definition of Done

Acceptance Criteria закрыты воспроизводимыми проверками. В реестре указаны SHA, PR, проверенная среда, результаты, ручная приёмка или основание «не применимо» и ограничения. Откат проверен в объёме задачи.
