# REL-02 — Production Readiness и управляемый rollout

Приоритет `P1`. [Реестр задач](../PROJECT-STATUS.md)

## Цель

Подготовить и при наличии разрешения выполнить управляемый выпуск с наблюдаемостью.

## Текущее состояние

Состояние production не проверено TASK 000. Фактический rollout и внешние подтверждения проходят отдельным этапом.

## Зависимости

[REL-01](REL-01-release-staging-rehearsal.md), [TPL-04](TPL-04-template-version-rollout.md), [AUTH-03](AUTH-03-live-production-gate.md)

## Scope

Первая партия ограничена принятыми версиями VF-01–VF-03. Последующие партии включают свои принятые версии. Для каждого кандидата сверяются версия, SHA и явная ручная визуальная приёмка.

Готовность конфигов, health/alerts, риск и rollback, smoke, согласованный rollout и release report.

## Non-goals

Несогласованные записи, destructive миграции, публикация пользовательских данных и продолжение при провале гейта.

## Архитектурные требования

Отдельное разрешение владельца на конкретный production write; match hash, flags по средам, redacted logs, связанная история deploy.

## План реализации

Проверить gates и backup; утвердить окно и команды; включать изменения поэтапно, наблюдать метрики; при отклонении выполнить откат.

## Acceptance Criteria

Релиз связан с Git SHA и проверками, разрешение и факт выкладки раздельны, опубликованные ссылки и данные сохранены.

## Обязательные тесты

Staging acceptance, authorized release smoke, provider events, health/metrics, rollback drill через защищённый стенд.

## Миграции

Только принятые аддитивные миграции с preflight и разрешением.

## Rollback Plan

Пауза rollout и workers; вернуться к предыдущему коду/flags и версии; schema оставить совместимой, при необходимости восстановить проверенный backup.

## Definition of Done

Acceptance Criteria закрыты воспроизводимыми проверками. В реестре указаны SHA, PR, проверенная среда, результаты, ручная приёмка или основание «не применимо» и ограничения. Откат проверен в объёме задачи.
