# TPL-03 — Репетиция обновления существующей коллекции

Приоритет `P0`. [Реестр задач](../PROJECT-STATUS.md)

## Цель

Проверить совместимость истории на двух последовательных запусках.

## Текущее состояние

Есть прежний локальный импорт и PostgreSQL-проверки; общей репетиции обновления всех существующих ID с инвариантами нет.

## Зависимости

[TPL-02](TPL-02-append-template-version.md)

## Scope

Репетиция append/publish на synthetic PostgreSQL и отчёт инвариантов.

## Non-goals

Рабочая БД, production медиа и одобрение визуальных отличий.

## Архитектурные требования

Синтетический набор содержит старые и новые версии, live/closed release, drafts, RSVP и общие ассеты.

## План реализации

Снять baseline ID/slug/hash; выполнить dry run, apply и retry; имитировать сбой/конкуренцию; сравнить snapshots и повторно открыть маршруты.

## Acceptance Criteria

Ни одного нового ID шаблона при обновлении; прежние черновики и гостевые релизы читаются; отмена оставляет базу согласованной.

## Обязательные тесты

Миграции новой и обновляемой БД при наличии изменения схемы, PostgreSQL E2E, smoke RU/KY и media/RSVP.

## Миграции

Проверить применимые миграции на disposable БД, без новых миграций в самой задаче.

## Rollback Plan

Вернуть scoped public pin на проверенную предыдущую версию тестовой БД; не удалять историю.

## Definition of Done

Acceptance Criteria закрыты воспроизводимыми проверками. В реестре указаны SHA, PR, проверенная среда, результаты, ручная приёмка или основание «не применимо» и ограничения. Откат проверен в объёме задачи.
