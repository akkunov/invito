# ACC-01 — Версионные миниатюры в кабинете

Приоритет `P1`. [Реестр задач](../PROJECT-STATUS.md)

## Цель

Показывать правильный дизайн версии приглашения в компактном списке.

## Текущее состояние

Обзор агрегирует список и ответы одним запросом; миниатюра отсутствует.

## Зависимости

[CAT-03](CAT-03-catalog-cover-jobs.md), [CAT-04](CAT-04-catalog-cards-and-editor.md), [ED-01](ED-01-draft-pinned-version.md)

## Scope

Thumbnail по фактическому типу и версии записи, размеры, placeholder, no-store owner scope.

## Non-goals

Новая выдача RSVP и повторная загрузка полных документов на каждую карточку.

## Архитектурные требования

Переиспользовать покрытие CAT и signed media без утечки других владельцев; различать draft и release.

## План реализации

Согласовать тип preview identity; расширить overview аддитивно; подключить компонент и fallback; снять запросы на нескольких страницах.

## Acceptance Criteria

Миниатюра не меняет дизайн старого черновика при publish V2; количество запросов ограничено; просрочка медиа восстанавливается.

## Обязательные тесты

API contract, PostgreSQL owner scopes, Playwright RU/KY, draft V1 vs V2, no image and expiry.

## Миграции

Нет сверх CAT-03, если имеющийся artifact contract подходит.

## Rollback Plan

Выключить миниатюры, сохранить список и overview.

## Definition of Done

Acceptance Criteria закрыты воспроизводимыми проверками. В реестре указаны SHA, PR, проверенная среда, результаты, ручная приёмка или основание «не применимо» и ограничения. Откат проверен в объёме задачи.
