# TPL-02 — Обновление дизайна новой версией

Приоритет `P0`. [Реестр задач](../PROJECT-STATUS.md)

## Цель

Обновлять уже существующий шаблон с CAS и безопасным повтором.

## Текущее состояние

Создающий импорт возвращает конфликт для существующего slug; версионный API уже есть.

## Зависимости

[TPL-01](TPL-01-template-identity.md)

## Scope

Dry run и append новой версии по проверенному ID, отделённая публикация.

## Non-goals

Новые шаблоны, массовый reimport, переписывание snapshot, фактический production rollout.

## Архитектурные требования

Переиспользовать DocumentsService, проверку пакета, медиа и полномочий; явно сверять expectedVersion и хеш. Повтор с тем же содержимым не создаёт новую версию.

## План реализации

Сформировать read-only diff; согласовать входные параметры; использовать каноническую запись версии; вернуть ID, версию, хеш и audit evidence.

## Acceptance Criteria

Отказ по stale CAS и чужому workspace; одинаковый повтор не создаёт версию; draft append не меняет public pin.

## Обязательные тесты

Backend unit/contract и PostgreSQL E2E на дубль, повтор, конфликт, доступ и порванную ссылку.

## Миграции

Нет по умолчанию; если текущего аудита/идемпотентности недостаточно, обосновать отдельную additive миграцию.

## Rollback Plan

Отключить новый путь. Уже созданная версия остаётся в истории; действующий указатель не меняется автоматически.

## Definition of Done

Acceptance Criteria закрыты воспроизводимыми проверками. В реестре указаны SHA, PR, проверенная среда, результаты, ручная приёмка или основание «не применимо» и ограничения. Откат проверен в объёме задачи.
