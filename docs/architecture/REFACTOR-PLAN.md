# Eventiq 4.0 — план реализации

Базовая ревизия и результаты проверок зафиксированы в [аудите](REFACTOR-AUDIT.md). Изменения раскладываются по проверяемым веткам с отдельным SHA. Перед слиянием обновляемся от `origin/main`, повторяем проверки и сохраняем изменения коллекции Studio v2.

## Архитектурные решения

### Каталог и редактор

**Решение.** TemplateVersion — immutable авторская версия. Template хранит отдельный указатель на публичную версию и обновляет его транзакцией с CAS. При append черновой версии действующий публичный указатель сохраняется. Опубликованное приглашение живёт в собственном release snapshot. `InvitationDraft.templateVersionId` продолжает ссылаться на исходную версию.

**Причина.** Карточка, detail, новый draft и полный рендер должны совпадать. Пользователь с черновиком должен открыть именно ранее выбранную версию даже после обновления каталога.

**Проверка и откат.** Таблицы и метаданные добавляются с fallback на исходное чтение, пока не завершён проверенный backfill. Переключение каталога выполняется только после сравнения выдачи. При проблемах возвращаем чтение на прежний код и сохраняем данные новых колонок; historical release snapshots, hashes и ключи draft не переписываем.

### Статические превью

**Решение.** Worker/CLI с ограниченной конкуренцией использует `StudioV2ProjectRenderer`, `coverPageId`, явную RU/KY locale, 430 CSS px, DPR 2, загрузившиеся шрифты, определённое состояние gated cover, отключённые анимацию, сетевые действия гостя и звук. Один job на version/locale/render revision. Входные URL разрешены только контрактом медиа. Результат WebP в R2 с высотой, шириной и состоянием. Повторный job сравнивает render hash. Seed-карточки проходят через тот же UI по адаптеру; цена неизвестного cloud-шаблона отображается как неизвестная модель доступа, фильтр цены действует на подтверждённые варианты.

**Причина.** Каталог отдаёт список компактных данных без полноразмерного JSON, сотен интерактивных renderer и Chromium на GET. Оригинальный hero можно проверить по той же системе слоёв.

**Проверка и откат.** Старые seed artwork остаются доступны. Для cloud при ошибке генерации применяется читаемый placeholder с названием. На список тестируем отсутствующую или просроченную подпись, частичную недоступность, дубликат slug, пагинацию, post-republish race и отсутствие чужих R2 ключей. Откат отключает генерацию и сохраняет уже вычисленные артефакты и прежние URLs detail.

### Идентичность и уведомления

**Решение.** Backend `AuthIdentity(provider, subject)` остаётся источником устойчивой идентичности. OAuth callback принимает только допустимый локализованный путь возврата и сохраняет anonymous draft перед переходом. Клиент сбрасывает приватные состояния по subject. В транзакции RSVP создаётся ровно одно outbox событие с уникальностью ответа и владельца. Worker получает lease, проверяет доступность канала и текущее согласие, повторяет временные ошибки ограниченное число раз. WABA templates локализованы, callback проверяет подписанное raw body, дедуплицирует provider event и обрабатывает доставку вне очереди. В событиях и логах держим только нужные данные, доступ к номеру и гостевым полям регулируется владельцем.

**Причина.** Повторы и внешняя недоступность не влияют на сохранение RSVP, а OAuth использует ту же проверку JWT и существующие учётные записи.

**Проверка и откат.** Email доступен при отключённом Google. Google client secret хранится в Supabase. Публичный endpoint RSVP не вызывает Meta. Флаг отключает enqueue и delivery, записи гостя остаются в PostgreSQL. Проверяем opt-out, повторный webhook, ошибки подписи, повторные отправки, лимиты на хозяина и частичный отказ. Live QA выполняется отдельно от adapter tests.

### Музыкальные провайдеры и воспроизведение

**Решение.** Backend registry `MusicProvider` возвращает typed track/reference `provider + stable id`, display metadata, длительность, доказательство прав, attribution и capabilities `seekable`, `duration`, `waveformAvailable`. Метаданные кешируются с TTL, ключом параметров запроса и явным ограничением размера. Rate limit с понятным 429, timeout и paginated normalized responses. `GET /api/v1/music/{search,providers}`, `tracks/:provider/:id`, `playback/:provider/:id` дополняют действующую `/catalog/music`. Playback resolver проверяет разрешения и выдаёт ограниченный безопасный URL от провайдера. Ключи только серверные. Храним ссылки и разрешённые метаданные, аудиобайты остаются у провайдера.

Studio v2 добавляет опциональные `MusicPlaybackSettings` к существующему музыкальному блоку. Тот же тип работает в local/cloud patch и immutable release. Frontend и backend проверяют `0 ≤ start < end ≤ duration`, громкость 0–1, конечные числа и длину fades. Значения по умолчанию должны сохранять старую семантику. Один shared player controller для библиотеки, редактора и публичного renderer. При выборе нового источника отменяет старую загрузку и воспроизведение. Seek выполняется после metadata и внутри seekable, конец останавливает audio или возвращает к start. Неподдерживаемые настройки скрываются или блокируются с локализованным объяснением. Программная громкость и fades деградируют без ошибок. Для waveform используем данные, разрешённые провайдером, и доступный slider или time inputs с шагом 1 секунда и кнопками ±5 с.

**Лицензирование.** У Audius есть API search/stream и поля лицензии. Доступ к потоку сам по себе не подтверждает права на коммерческое приглашение, композицию, запись и обработку фрагмента. Статус лицензии проходит явную модерацию и может быть отозван независимо от сохранённого snapshot. Для Jamendo коммерческий доступ требует отдельного соглашения. Openverse предоставляет метаданные и не заменяет проверку лицензии у источника. Feature flags внешних источников выключены до проверки прав, в том числе attribution и допустимости фрагмента. [Audius API](https://docs.audius.co/api/) · [Audius Terms](https://audius.co/documents/TermsOfUse.pdf) · [Jamendo API Terms](https://devportal.jamendo.com/api_terms_of_use) · [Openverse Terms](https://docs.openverse.org/terms_of_service.html)

**Проверка и откат.** Проверяем поиск по исполнителю/названию, debounce и отмену, успешный и пустой результат, пагинацию, attribution, отозванные и недоступные источники, реальный Range и mobile play, локальные треки, solo playback, undo/redo, сохранение и опубликованное приглашение. Отключение provider flag сохраняет snapshot и метаданные. Публичная страница при ошибке внешнего разрешения продолжает работать без этого аудио.

### Сохранение и refactor

После визуального согласования кабинет и редактор используют токены `--ed-*` для внешних поверхностей. Внутри приглашения дизайн принадлежит шаблону. `UniversalMobileEditor`, `UniversalSectionManager`, `SimpleField`, `MobileTypographyControls` и `StudioV2ProjectRenderer` остаются используемыми точками расширения. Reducer или существующие команды отвечают за атомарную историю. Автосохранение debounced, привязано к session generation и draft ID. CAS защищает от параллельных вкладок. Перед publish нужно дождаться подтверждения записи последней ревизии. Старые localStorage значения читаются как явный кандидат восстановления без автоматического переноса между аккаунтами.

Переиспользуем Nest-модули и общий Zod contract. Изменения в доменном API проходят через существующий OpenAPI registry. Отдельные задачи для миграций, UI, CI и удаления кода используют независимые rollback: выключение нового чтения, отложенная обработка worker, переход к прежнему chrome, возврат адаптера. Для удаления требуется проверенная совместимость persisted snapshots, route и CSS consumer, dynamic import, static bundles и tests.

## Визуальные концепты для согласования

- **Кабинет.** Мобильная и десктопная компоновки с краткой статистикой, карточкой опубликованного приглашения и ответами гостей. Счётчики и данные в образце синтетические. [Концепт кабинета](qa/concepts/account.webp)
- **Редактор.** Мобильный холст, нижняя панель и контекстное окно, десктопный холст между списком секций и настройками. Иллюстрация приглашения на концепте служит для проверки масштаба холста. Реальный редактор использует оригинальные renderer и шаблон. [Концепт редактора](qa/concepts/editor.webp)

## Контроль перед слиянием

- Запустить frontend `npm run typecheck`, `npm run lint`, `npm run build`, регрессии шаблонов, `npm run test:template-assets` и feature suite. Для API выполнить `npm run typecheck`, `npm run build`, `npm test`, `npm run db:migrate:deploy` и `npm run test:e2e` на отдельной PostgreSQL. CI должен показывать отдельные unit и E2E результаты.
- Проверить браузеры при 320/360/375/390/412/430 px и desktop, touch/keyboard, RU/KY, длинные имена, preview/RSVP, HEIC, сохранение, повторную публикацию, смену сессии и истечение подписи. Для производительности сравнить число HTTP/SQL и JS bytes на одинаковом fixture. Полевые p75 LCP/INP/CLS измерять отдельно от лабораторного запуска.
- Приложить SHA, список изменений и тестов, реальные снимки, migration/rollback, статус live Google, Meta и R2, примеры env без секретов. Документировать неподдержанные состояния и реальные ограничения тестовой среды.

```powershell
git fetch origin main
npm ci
npm run typecheck
npm run lint
npm run build
npm run test:template-assets
npm ci --prefix server
npm run typecheck --prefix server
npm run build --prefix server
npm test --prefix server
# DATABASE_URL и DIRECT_DATABASE_URL указывают на отдельную тестовую PostgreSQL.
npm run db:migrate:deploy --prefix server
npm run test:e2e --prefix server
```
