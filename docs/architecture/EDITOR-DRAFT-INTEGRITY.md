# ED-01 / ED-02 — целостность черновиков

Ветка `feat/eventiq-4-1-editor-draft-integrity` от [beff999](https://github.com/akkunov/invito/commit/beff999b0e61d1f45b5ea433a548bd907e257ca7). Статус REVIEW. Для ручной проверки используются локальный fixture и отдельная PostgreSQL.

## Контракт

- `/ru/editor?draft=<id>` и старые ссылки с `template` и `draft` открывают черновик по ID. Nest проверяет владельца и выдаёт исходный контракт, документ и временные URL медиа через `GET /api/v1/customer/invitations/:id/editor-source` с `private, no-store`. Версия берётся из связи черновика. Идентификатор чужого черновика даёт 404. Редактор загружается после входа.
- Новый черновик берёт опубликованную версию. При открытии браузер записывает версию в URL и сохраняет её в возврате из OAuth. Если каталог успел сменить версию до следующего открытия, интерфейс сообщает об этом и сохраняет прежние локальные данные. Такой гостевой черновик без облачного ID не получает доступ к закрытой исторической версии.
- Копия версии на устройстве изолирована по subject, ID версии и ID черновика. «Новый черновик» открывает отдельный локальный UUID. Ссылки на облачные копии запускают их отдельные рабочие пространства. При первом сохранении API атомарно создаёт черновик со снимком правок. После сохранения редактор открывает постоянный URL. Существующий POST без patch продолжает создавать пустой черновик.
- У локального снимка есть исходная облачная ревизия для CAS. При конфликте локальные данные остаются в редакторе. «Загрузить сохранённое» явно заменяет локальные правки облачной копией после подтверждения. Для старых снимков v2 без ревизии облачное сохранение требует предварительного чтения этой копии.
- Общие сохранённые ссылки гостей и опубликованные снимки используют прежние API. Миграций БД нет.

## Безопасное восстановление v1

В старом общем ключе хранится версия шаблона, но отсутствует связь с владельцем и конкретным приглашением. Согласие текущего пользователя, совпадение версии, наличие media ID и вход в аккаунт сами по себе не подтверждают происхождение текста. Поэтому редактор сохраняет v1 на устройстве и исключает его чтение и показ в обычной сессии.

1. Войдите в аккаунт, которым приглашение было сохранено. Откройте его из «Мои приглашения». Облачный снимок возвращается только владельцу и только для выбранного ID.
2. Если этого требует состояние редактора, нажмите «Загрузить сохранённое» и подтвердите замену локальных правок текущей копии. Это восстанавливает последнюю сохранённую облачную ревизию.
3. Правки, существующие только в непривязанном v1, автоматически восстановить безопасно нельзя. При наличии отдельной резервной копии с независимо подтверждённым владельцем исходные значения можно повторно внести через редактор этого владельца. Общий v1 сохраняется без удаления.

## Windows PowerShell

Используйте [локальный стенд Chromium](AUTH-SESSION-AUDIT.md#1-изолированная-проверка-chromium) на ветке `feat/eventiq-4-1-editor-draft-integrity`. Можно выбрать установленный Chromium-совместимый браузер.

```powershell
git fetch origin
git switch feat/eventiq-4-1-editor-draft-integrity
$env:CHROMIUM_PATH = "C:\Path\To\chrome.exe"
npm.cmd run test:google-auth
npm.cmd run test:auth-session-browser
```

Браузерная матрица проверяет V1 после публикации V2, изоляцию двух черновиков одного владельца, reload, выход, смену аккаунта, OAuth и исключение чтения v1. На отдельном тестовом API можно повторить вручную через две записи в «Мои приглашения» и кнопку «Новый черновик». Проверки живого Google и email относятся к [AUTH-03](tasks/AUTH-03-live-production-gate.md).
