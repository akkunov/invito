# Eventiq 4.0 — аудит архитектуры

Аудит выполнен на `origin/main` [`f9f2cbbb1ff1ae731150850e9a846ccf9cbe7e26`](https://github.com/akkunov/invito/commit/f9f2cbbb1ff1ae731150850e9a846ccf9cbe7e26) 24 ноября 2026 года по времени Бишкека. На этой ревизии уже интегрирована коллекция из десяти дизайнов. Аудит охватывает исходный код, контракты и документацию. Измерения сделаны локально с синтетическими данными и отдельной PostgreSQL 17.

## Архитектура и маршруты

| Поверхность | Точка входа | Источник данных и границы |
| --- | --- | --- |
| Лендинг и каталог | `/[locale]`, `/[locale]/templates`, `/[locale]/catalog` | Next.js App Router. Статический реестр встроенных дизайнов и публичный Nest API продолжают жить рядом. `/[locale]/catalog/[slug]` отображает облачный документ через `StudioV2ProjectRenderer`, `/[locale]/templates/[slug]` показывает встроенный дизайн. |
| Клиентский редактор | `/[locale]/editor?template=…&draft=…` | `InvitationEditor` для встроенных шаблонов, `CustomerMobileEditor` для серверных. Оба используют `UniversalMobileEditor` на мобильных устройствах. Последний также применяет ограниченный `personalization` patch через общее доменное ядро. Старый формат локальных приглашений обслуживает `/[locale]/i/[slug]`. |
| Кабинет | `/[locale]/invitations` | `CustomerInvitationsDashboard`, Supabase session, приватные запросы черновиков, публикаций и ответов. Маршрута `/[locale]/account` пока нет. |
| Admin Studio v2 | `/[locale]/admin/studio-v2`, прежний `/admin/studio` | Полный авторский холст, типизированные команды и история, responsive overrides, локальные проекты, удалённые revisions, публикация шаблонов. Customer editor должен продолжать получать только разрешённые поля. |
| Публичная ссылка клиента | `/[locale]/c/[slug]` | Действующий `CustomerPublicationRelease` с immutable snapshot и SHA-256. RSVP связан с версией и опубликованным widget. |
| API / БД | `server/src/app.module.ts`, `server/prisma/schema.prisma` | Nest-модули Auth, Workspaces, Documents, Media, Catalog, Publications, CustomerInvitations. PostgreSQL хранит workspace membership, версии, revisions, immutable releases, RSVP и throttle. Prisma настроен на независимый direct connection для миграций. |
| Файлы и проигрывание | `src/lib/prepare-local-photo.ts`, `server/src/modules/media`, `/api/v1/catalog/music` | Клиентская нормализация фото с HEIC, серверная верификация загрузки, private R2 и подписанные URL. Локальные музыкальные источники, выбранные из разрешённого списка, живут в snapshot. |

Код совместно использует Zod-схемы `src/features/studio-v2/core` и правила server domain из `server/domain/persistence-contract.ts`. Браузерные интеграции находятся отдельно от core. В Next-проекте фактически установлены Next.js 16.4.6, React 19.3.1, Zod 4.6.7 и Supabase SSR 0.7.0. В API установлены NestJS 12.5.1 и Prisma 7.10.1. У обоих пакетов есть lockfile. На этапе 0 использовался Node.js 24.22.3, CI закрепляет Node 22.

Изучены существующие ADR для persistence, sync, media и publishing, шаблонный импорт и страницы Studio v2, `DESIGN.md`, `UX-CONTRACT.md`, миграции, OpenAPI и CI. Для дальнейшей работы сохраняем [архитектуру Studio v2](../studio-v2/ARCHITECTURE.md), [правила публикации](../backend/ADR-029-05-PUBLISHING.md), [схему импорта](../backend/TEMPLATE-PACKAGE-V1.md) и [контракты коллекции](../studio-v2/TEMPLATE-COLLECTION.md).

## Исходные результаты проверок

- **Frontend.** Typecheck и production build на исходном SHA прошли. В начале аудита `npm run lint` вернул 78 ошибок и 53 предупреждения. Частые причины — React Hooks, `any` и неиспользуемые импорты. Из 43 npm-команд вне отдельного браузерного набора прошли 40 при параллельном запуске. `test:riviera` ошибочно требовал пробелы в выражении ограничения размера галереи. `test:monochrome-editorial` падал из-за отсутствия WebP. `test:public-routes` не дождался старта тестового процесса под параллельной нагрузкой и прошёл отдельно после сборки.
- **Backend.** Typecheck и production build прошли. На PostgreSQL 17 применились шесть миграций. `npm test` — 18/18, `npm run test:e2e` — 5/5. E2E проверяет локальный JWT, ownership, ревизии/CAS, модель media/R2 и публикацию с RSVP. Облачный бакет и production-БД в этих запусках не использовались.
- **Browser и Playwright.** Browser открыл каталог и detail Love Story с полным дизайном. В Chromium при DPR 1 сняты 390 × 844, 430 × 844 и 1440 × 960. При 390 px дополнительно проверена кыргызская локаль всех четырёх экранов. Исходный скриншот Monochrome Editorial показывает пустые места в обложке и галерее. Снимки 430 px и desktop сделаны повторно после сборки с исправленными статическими файлами. Представление каталога, редактора и кабинета этой сборки совпадает с проаудированной реализацией по коду. Приватный кабинет зафиксирован в состоянии отсутствующей конфигурации Supabase; login, Google и Meta live на этом этапе не проверялись.

### Локальные сетевые измерения

Каждый экран открыт с чистой browser context и синтетическим каталогом из трёх облачных шаблонов. Resource Timing фиксирует запросы, видимые клиенту, и сумму encoded body size загруженных same-origin JS-скриптов в байтах. SSR API-вызовы, префетч после окна измерения и полевой Core Web Vitals здесь отдельно не измерены. Повторные значения сняты на production-сборке после восстановления файлов. Показатели зависят от viewport и загружаемых Next chunks.

### Доказательства перед удалением кода

Точек входа для немедленного удаления аудит не нашёл. `src/components/invitation/*` вызывается старыми публичными маршрутами и seed detail. `/admin/studio` участвует в static preview CI. `/catalog` имеет публичные ссылки. Перечень кандидатов на следующую фазу — отдельный `ServerCatalogGrid` после миграции потребителей, логика старых листингов после объединения фильтров, повторяемые auth-формы после переключения всех пользовательских вызовов. Для каждого кандидата проверяем route files, dynamic imports, npm scripts, CSS hooks, bundle graph, историю snapshot и браузерный сценарий. Отдельный PR удаляет только подтверждённые зависимости.
