## Правила статуса и передачи контекста

- `TODO` — задача ещё не взята. `IN_PROGRESS` — ведётся работа на указанной ветке. `BLOCKED` — работа упирается в конкретный внешний ресурс или разрешение, указаны условие возобновления и действие.
- `REVIEW` — есть результат для проверки, остаётся ревью/приёмка. `ACCEPTED` — подтверждена требуемая ручная или внешняя приёмка конкретного SHA/версии. `DONE` — выполнен DoD, есть подтверждённые проверки и итог требуемого merge/доставки. Для непроизводственных задач шаги выкладки применяются только по scope.
- Во время handoff обновить строку и карточку. Указать SHA реализации, PR, реальные команды/результаты со средой, артефакты, принятую/непринятую ручную проверку и точную следующую операцию. Поле «ветка» помечает будущие ветки словом «план». «—» в SHA означает отсутствие реализации этой задачи. Зафиксировать SHA источников при отличии от SHA реализации.
- Проверенность кода на Git и выкладка в рабочую среду ведутся раздельно. Исторический PASS относить к его SHA и объёму проверки. Если приёмка визуальная, сохранять оригинал, render, diff, параметры viewport и её решение. Тесты шаблона сами по себе не переводят его в `ACCEPTED`.
